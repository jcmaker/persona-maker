# confidence-levels.md — 신뢰도 3등급 체계

> **대상 독자:** 이 문서는 `generate`/`generate --update` 스킬과 persona-generator
> 서브에이전트가 페르소나의 신뢰도 등급(`confidence`)을 정하고 갱신할 때 그대로
> 따라야 하는 규칙이다. AI가 합성한 페르소나는 실제 인터뷰 없이도 그럴듯하게
> 보이도록 생성되기 쉽다 — 이 등급 체계는 "이 페르소나가 얼마나 검증됐는지"를 항상
> 명시적으로 드러내기 위한 방어 장치다. 등급을 생략하거나 감으로 정하는 것을
> 금지한다.

## 1. 3등급 기준표

| 등급 | 조건 | 카드 상단 표시 |
|---|---|---|
| `assumption` | 아이디어 설명만으로 AI가 생성한 proto-persona. 뒷받침하는 인터뷰가 0건. | ⚪ 배너(문구는 §4) |
| `partial` | 인터뷰 1~2건이 이 페르소나의 일부 속성을 뒷받침한다. | 🟡 검증된 속성 / 가정에 머문 속성을 구분 표기 |
| `validated` | 인터뷰 3건 이상이 이 페르소나의 핵심 속성(`goals`·`frustrations`·`behaviors` 중 다수)을 뒷받침한다. | 🟢 속성별 출처 인용 링크 |

등급은 인터뷰 "건수"만으로 정해지지 않는다. 인터뷰가 있어도 그 페르소나의 속성과
무관하면 근거로 세지 않는다. `sources`에 실제로 연결된, 관련성이 확인된 인터뷰만
근거로 인정한다.

**프로젝트 전체 표본이 3명 미만이면 이 표보다 우선하는 상한이 있다** — §3(편향
경고) 참조.

## 2. 승격 규칙

`research/`에 인터뷰가 추가되고 `generate --update`가 실행되면 다음 절차를
따른다.

1. 신규 인터뷰의 증거 문장(`[I-NN]` 태그, `interview-analysis.md` 참조)이 이
   페르소나의 어떤 속성(`goals`/`frustrations`/`behaviors`/`demographics` 등)과
   대응하는지 확인한다. 억지로 끼워 맞추지 않는다.
2. 대응이 확인되면 해당 인터뷰 파일 경로를 `sources` 리스트에 추가한다(중복 추가
   금지).
3. `sources`에 연결되고, 이 페르소나와 실제로 관련된 인터뷰 수를 센다.
   - 0건 → `assumption` 유지
   - 1~2건 → `partial`로 승격(기존 `assumption`이었다면)
   - 3건 이상 → `validated`로 승격(기존 `partial` 또는 `assumption`이었다면)
4. 인터뷰 3건이 한 번에 들어오면 `assumption` → `validated` 직행도 허용한다. 단
   §1·§3의 조건을 실제로 만족해야 한다.

## 3. 강등 규칙

승격만 있는 것이 아니다. 새 인터뷰가 기존 가정과 모순되면 다음을 따른다.

1. 모순되는 속성(`goals`/`frustrations`/`behaviors`의 특정 항목)을 인터뷰 내용에
   맞게 수정한다. 원래 내용을 그냥 지우지 말고, 본문에 "이전 가정: …" 형태로 무엇이
   왜 바뀌었는지 남긴다.
2. 해당 페르소나가 `validated`였다면 `partial`로 강등한다. 모순이 여러 핵심
   속성에 걸쳐 있으면 `assumption`까지 강등할 수 있다.
3. 강등 사유는 `--update` 실행 결과 보고에 명시한다(어떤 속성이 왜 바뀌었는지).

### 편향 경고와의 관계 (표본 부족 상한)

`interview-analysis.md`의 편향 경고 규칙에 따라, **프로젝트 전체에서 서로 다른
참가자(별칭 기준) 수가 3명 미만이면 어떤 페르소나도 `partial`을 넘는 등급을 받을 수
없다.** 이는 특정 페르소나의 `sources` 개수가 기준을 만족해 보여도 마찬가지다 —
전체 응답자 풀이 좁으면 그 소수 응답이 여러 페르소나에 걸쳐 과대 해석됐을 위험이
크기 때문이다. 이 상한이 §1의 개별 등급 조건보다 우선한다.

## 4. 고지 문구 (원문 그대로 사용)

`assumption` 등급 카드는 시각화·본문 상단에 다음 배너를 **정확히 이 문구로**
표시해야 한다. 의역·축약·생략 금지:

> ⚪ 가정 기반 proto-persona — 실사용자 검증 전에는 중요한 의사결정 근거로
> 사용하지 마세요.

## 5. 등급별 표시 규칙

- **assumption ⚪**: 위 §4 배너를 카드 최상단에 표시한다.
- **partial 🟡**: 속성 단위로 "검증됨"과 "가정"을 구분 표기한다. 예: `goals`의 각
  항목 옆에 `sources`로 뒷받침되면 `(검증)`, 아니면 `(가정)`이라 표시한다.
- **validated 🟢**: 속성 단위로 어떤 인터뷰가 근거인지 인용 링크(`[I-NN]` 또는
  인터뷰 파일 경로)를 붙인다.

## 6. `--update` 실행마다 점검 체크리스트

- [ ] 신규 인터뷰의 `[I-NN]` 태그가 이 페르소나 속성과 실제로 대응하는가(억지
      연결 금지)
- [ ] `sources` 리스트가 실제 대응된 인터뷰만 포함하는가
- [ ] 프로젝트 전체 참가자 수가 3명 미만이면 `partial`을 넘는 등급을 부여하지
      않았는가
- [ ] 등급이 §1 조건을 만족하는가(건수 세기 전에 관련성부터 확인)
- [ ] 모순 발견 시 강등을 빠뜨리지 않았는가
- [ ] `assumption` 카드는 §4 배너 문구를 정확히 포함하는가
