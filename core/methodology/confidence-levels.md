# confidence-levels.md — The 3-Tier Confidence System

> **Audience:** This document is the rule set that the `generate` /
> `generate --update` skill and the persona-generator subagent follow verbatim
> when setting and updating a persona's confidence grade (`confidence`).
> AI-synthesized personas are easily generated to look plausible without any
> real interviews — this grading system is a safeguard that always makes "how
> validated is this persona" explicit. Omitting the grade or setting it by gut
> feeling is forbidden.

## 1. The 3-tier criteria table

| Grade | Condition | Card header indicator |
|---|---|---|
| `assumption` | A proto-persona generated by AI from the idea description alone. Backed by 0 interviews. | ⚪ banner (wording in §4) |
| `partial` | 1–2 interviews back some of this persona's attributes. | 🟡 mark validated attributes vs. attributes still assumed |
| `validated` | 3+ interviews back this persona's core attributes (a majority of `goals`/`frustrations`/`behaviors`). | 🟢 per-attribute source citations |

The grade is not determined by interview "count" alone. Even if an interview
exists, it does not count as evidence if it is unrelated to the persona's
attributes. Only interviews actually linked in `sources`, with confirmed
relevance, count as evidence.

**If the project's total sample is fewer than 3 participants, a cap takes
precedence over this table** — see §3 (bias warning).

## 2. Promotion rules

When an interview is added to `research/` and `generate --update` runs, follow
this procedure.

1. Confirm which attribute of this persona
   (`goals`/`frustrations`/`behaviors`/`demographics`, etc.) each evidence
   sentence of the new interview (`[I-NN]` tag, see `interview-analysis.md`)
   corresponds to. Do not force-fit.
2. Once a correspondence is confirmed, add that interview file path to the
   `sources` list (no duplicate additions).
3. Count the interviews linked in `sources` that are actually relevant to this
   persona.
   - 0 → stay `assumption`
   - 1–2 → promote to `partial` (if previously `assumption`)
   - 3+ → promote to `validated` (if previously `partial` or `assumption`)
4. If 3 interviews arrive at once, a direct `assumption` → `validated` jump is
   allowed. But the §1 and §3 conditions must actually be met.

## 3. Demotion rules

Promotion is not the only direction. When a new interview contradicts an
existing assumption, follow this.

1. Revise the contradicted attribute (a specific item in
   `goals`/`frustrations`/`behaviors`) to match the interview. Do not simply
   delete the original — leave a "Previous assumption: …" note in the body
   stating what changed and why.
2. If the persona was `validated`, demote it to `partial`. If the contradiction
   spans multiple core attributes, you may demote all the way to `assumption`.
3. State the demotion reason in the `--update` run report (which attribute
   changed and why).

### Relationship to the bias warning (small-sample cap)

Per the bias-warning rule in `interview-analysis.md`, **if the number of
distinct participants (by alias) across the whole project is fewer than 3, no
persona may receive a grade above `partial`.** This holds even if a specific
persona's `sources` count appears to meet the criterion — a narrow respondent
pool means a few responses risk being over-interpreted across many personas.
This cap takes precedence over the per-grade conditions in §1.

## 4. Disclosure text (use verbatim)

An `assumption`-grade card must display the following banner **with this exact
wording** in the visualization and card body. No paraphrasing, shortening, or
omission:

> ⚪ Assumption-based proto-persona — do not use as a basis for important
> decisions before validating with real users.

## 5. Per-grade display rules

- **assumption ⚪**: Display the §4 banner at the top of the card.
- **partial 🟡**: Mark "validated" vs. "assumed" per attribute. Example: next to
  each `goals` item, mark `(validated)` if backed by `sources`, otherwise
  `(assumed)`.
- **validated 🟢**: Attach a citation link (`[I-NN]` or interview file path) per
  attribute showing which interview is the evidence.

## 6. Per-`--update` checklist

- [ ] Does the new interview's `[I-NN]` tag actually correspond to this persona's attribute (no forced links)?
- [ ] Does the `sources` list contain only actually-corresponding interviews?
- [ ] If the project's total participants are fewer than 3, did you avoid granting a grade above `partial`?
- [ ] Does the grade satisfy the §1 conditions (check relevance before counting)?
- [ ] When a contradiction is found, did you not skip the demotion?
- [ ] Does the `assumption` card include the §4 banner wording exactly?
